Overview: This reference guide documents the XML data structure for the Labour Market Development Agreements (LMDA) and Workforce Development Agreements (WDA) interface, based on Schema Version 1.5. It outlines required elements, expected data types, mandatory conditions, and structural hierarchies for the federal–provincial data exchange with ESDC.

Legend: M = Mandatory  |  C = Conditional  |  O = Optional  |  NEW in 1.5 = Added in Schema 1.5  |  UPDATED = Modified in Schema 1.5

★ Version 1.5 — Change Summary

Schema 1.4 → 1.5 key changes (consolidated from change history):
  • Metadata: Added <sysAction> element for record-level data salvage (logical deletion).
  • Client §1.5.6: Email mandatory for tariff was added (2025/11/03) then removed (2026/03/16). Appendix F still lists it as mandatory—see note in Appendix C.
  • Action Plan: Added Previous Multiple Employment, Employer Name, Previous Employment Date/Pay Rate/Hours, Previous NAICS & Version, Target NAICS & Version, Precarious Employment. Added Work-sharing (7) to previous employment and result codes; added Starting new action plan (8) to result codes.
  • Follow-Up / Contact: New section (Section 4). Added Follow-Up Result Date, Multiple Employment, NOC Version, NAICS, NAICS Version. Follow-up date and result code are conditional (mandatory for tariff). Work-sharing added to result codes.
  • Intervention: Added <interventionSupport> wrapper [0..10] containing Cost, Cost Category, Cost Category Comment. Added Language of Service (mandatory) and Credential/Certificate. Related NOC expanded to Numeric(5) for NOC 2021; mandatory conditions tightened for tariff and specific intervention codes.
  • Appendixes: Added Appendix F (Mandatory Tariff Field Description) and Appendix G (Complete Tariff XML Example).

3. Action Plan Data Model

An Action Plan represents a participant's service episode and contains one or more interventions. A client may have multiple action plans over time, but only one may be open at a time — the previous plan must be closed (with a Result Code and Result Date) before a new one can begin. Nested within <content><client><actionPlan>.

⚠ Tariff Note: When actionPlanFundingSource is 1, 2, or 3 (tariff-related), several additional fields become mandatory. See Appendix C for the complete list.

Employer Name<actionPlanFollowUpEmployerName>AlphaNum(100)CEmployer at follow-up. Mandatory when resultCode = 2 (Employed) or 7 (Work-sharing) AND previousEmployment = 1, 3, or 6.

Current NOC<actionPlanFollowUpNOC>Numeric(5)CNOC at follow-up. Mandatory when resultCode = 2, 3, or 7 AND fundingSource = 1, 2, 3 AND followUpDate is provided.
Current NOC Version NEW in 1.5<actionPlanFollowUpNOCVersion>Numeric(4)CNOC version: 2011, 2016, or 2021. Mandatory when followUpNOC is provided.

⚠ Field Name Note: The source document Appendix F uses shortened field names (actionPlanFollowUpPayRate, actionPlanFollowUpHours), but the XML schema uses the full names with “Employment” (actionPlanFollowUpEmploymentPayRate, actionPlanFollowUpEmploymentHours). Always use the full XML tag names in submissions.

4.1 Intervention Support NEW in 1.5

Wrapper element <interventionSupport> nested within each <intervention>. Up to 10 occurrences per intervention.

Element NameXML TagFormatReq.Description
Cost NEW in 1.5<interventionCost>Numeric(6)CDollar amount. Range: 1–999999. No decimals. Mandatory when fundingSource = 1, 2, 3 AND (interventionOutcome or actionPlanResultCode is provided) AND costCategory is provided.
Cost Category NEW in 1.5<interventionCostCategory>Numeric(2)C0 = N/ A, 1 = Transportation, 2 = Dependent support, 3 = Accommodations, 4 = Disability support, 5 = Mental health, 6 = Supplies, 7 = Mobility/relocation, 8 = Tuition/fees, 10 = Other. 5. sysAction — Data Salvage NEW in 1.5

The <sysAction> element enables record-level logical deletion for data correction and salvage. It is a complex element nested within <content> containing sub-elements that identify the target record to be removed.
